3 issues in the test code (and how to fix them)

Below are three common problems in the code snippet you shared, why they matter, and a clean Playwright + pytest way to fix them. The goal is to make tests reliable, fast, and easy to debug.

Issue 1 — Starting Playwright incorrectly + not cleaning up properly

Problem The code uses sync_playwright().start() without a context manager and never calls p.stop(). This can leak Playwright driver processes and make later tests flaky.

Why it’s a problem

  • Resource leak: leaving Playwright running can keep background processes alive.
  • Flaky suite: leaks often show up as random failures in CI or after many tests.

Fix (use a context manager)

from playwright.sync_api import sync_playwright

def test_search_functionality():
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto("https://example.com")
        # ... test steps ...
        browser.close()

Even better (pytest fixtures)

Put browser setup/teardown in conftest.py fixtures (like this project already does), so each test only focuses on the scenario.

Issue 2 — Using time.sleep instead of waiting for real conditions

Problem time.sleep(2) and time.sleep(3) wait a fixed amount of time. Sometimes the page is slower (test fails), sometimes faster (test wastes time).

Why it’s a problem

  • Flakiness: sleeps don’t guarantee the element is ready.
  • Slow tests: even when the UI is ready immediately, you still wait the full sleep time.

Fix (wait for an element / URL / text)

from playwright.sync_api import expect

# Wait for the search box to be visible/enabled
search_box = page.locator("#search")
expect(search_box).to_be_visible()
search_box.fill("playwright testing")

# Wait for results to appear
results = page.locator(".result-item")
expect(results.first).to_be_visible()

Issue 3 — No assertion (the test doesn’t actually verify anything)

Problem The code creates results = page.locator(".result-item") but never checks that results exist or match expectations. Without an assertion, the test can “pass” even when the feature is broken.

Why it’s a problem

  • False confidence: the test might always pass and catch nothing.
  • Harder debugging: you don’t know what “correct” means for the test.

Fix (assert something meaningful)

from playwright.sync_api import expect

results = page.locator(".result-item")

# Example: at least 1 result
expect(results).to_have_count(1)

# Or: assert that the first result contains expected text
expect(results.first).to_contain_text("playwright")
Extra note: The snippet also imports Selenium (from selenium import webdriver) but never uses it. Mixing frameworks in one test is usually unnecessary—pick one (here: Playwright) to keep your suite consistent.
